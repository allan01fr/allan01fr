> **Para agentes:** SUB-SKILL OBRIGATÓRIA: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para implementar este plano tarefa a tarefa. Os passos usam checkbox (`- [ ]`) para acompanhamento.

**Objetivo:** criar `suite/` com o núcleo (config, banco, login, perfis, empresa, erros, unidades, arquivos, fila de tarefas), o módulo `cadastro` (clientes → empreendimentos → ambientes → ativos, com importação em lote), as telas PWA, o docker-compose local e o CI. Isso entrega o critério de pronto da T0.

**Arquitetura:** monólito modular. Um back-end FastAPI síncrono (SQLAlchemy 2 + psycopg 3) com `app/nucleo/` e `app/modulos/cadastro/`, um worker (mesmo código, outro processo) que consome a tabela `tarefa` com `FOR UPDATE SKIP LOCKED`, PostgreSQL 16 e armazenamento S3 compatível (MinIO no ambiente local). O front-end é React + TypeScript + Vite, instalável como PWA, e usa tipos gerados do OpenAPI do back-end.

**Tecnologia:** Python 3.12, FastAPI, Pydantic v2 (+ pydantic-settings, email-validator), SQLAlchemy 2, Alembic, psycopg 3, argon2-cffi, itsdangerous, boto3, pytest, httpx, moto, ruff. Node 22, React 19, react-router 7, Vite 6, vite-plugin-pwa, Vitest, Testing Library, ESLint 9, openapi-typescript 7, Playwright. Docker Compose, GitHub Actions.

**Especificação:** `docs/superpowers/specs/2026-11-08-suite-hvacr-design.md` (seções 2, 3, 4, 5, 6-T0 e 8). Os requisitos adicionais de cadastro vieram do usuário pelo coordenador: hierarquia com `ambiente`, cliente PF/PJ com representante legal, `arquivado_em`, importação em lote e configuração da empresa com responsáveis técnicos.

## Restrições globais

- Python `>=3.12,<3.13` (o python-hvac exige < 3.13). PostgreSQL 16. Node 22.
- Back-end: FastAPI + Pydantic v2 + SQLAlchemy 2 (síncrono, `postgresql+psycopg`) + Alembic. Rotas `def` (não `async`).
- Fila de tarefas: tabela `tarefa` no PostgreSQL com `FOR UPDATE SKIP LOCKED`. Sem Redis nem broker.
- Login com e-mail e senha (hash argon2) e sessão em cookie `httpOnly` assinado. O cookie se chama `suite_sessao`, com `SameSite=Lax` e `Secure` vindo de `SUITE_COOKIE_SEGURO`.
- Os perfis são exatamente `admin`, `engenharia`, `comercial`, `financeiro` e `campo`. A matriz de permissões fica em `app/nucleo/perfis.py`.
- Toda tabela, exceto `empresa`, tem `empresa_id` não nulo. Consultas de módulo partem só de `RepositorioBase.consulta()`.
- Erro único: `{"codigo": "...", "mensagem": "...", "detalhes": {...}}`, com mensagens em português e sem rastreamento interno.
- O banco e a API usam SI (W, m³/h, m, m², Pa, °C, kg). Constantes de conversão só em `app/nucleo/unidades.py`.
- O fluxo de cada módulo é `rotas.py → esquemas.py → servico.py → repositorio.py → modelos.py → tarefas.py`. Outro módulo só usa `servico.py`, e o serviço devolve esquemas `*Saida`, nunca objetos ORM.
- A rota nunca espera uma tarefa longa: `enfileirar(...)` devolve o id e o estado é consultado depois.
- IDs são UUID v4. Nomes de código, tabelas, rotas e mensagens em português.
- Nenhum segredo no repositório. Todas as variáveis `SUITE_*` ficam documentadas em `suite/.env.example`, e `suite/.env` é ignorado pelo git.
- Nenhum valor tirado de norma ABNT no código (regra 9 da especificação). Só a classificação de nível de risco (inteiro 0–3) aparece, sem parâmetros.
- Qualidade: um assunto por arquivo, legível por um júnior, o mesmo fluxo para o mesmo tipo de trabalho. `ruff check` e `ruff format --check` com `line-length = 100`. ESLint no front-end.
- Comandos do back-end rodam em `suite/backend/`, e os do front-end em `suite/frontend/`. O banco local sobe com `docker compose -f ../infra/docker-compose.yml --env-file ../.env up -d banco s3 cria-balde`.
- Migrações Alembic com `--rev-id` sequencial (`0001`…`0007`) e uma migração por tarefa que cria tabela.

## Pontos de atenção na revisão

1. **Referência de outra empresa no corpo.** Quando `cliente_id`, `obra_id` ou `ambiente_id` de outra empresa vem no JSON ou na importação, o sistema responde 404 "… não encontrado." e não grava nada. Teste nas Tarefas 14, 15 e 16.
2. **E-mail com maiúsculas ou espaços no login, e e-mail inexistente.** O login aceita `"  Ana@A.com "`. E-mail inexistente e senha errada dão a mesma resposta 401 `credenciais_invalidas`. Teste na Tarefa 7.
3. **CPF/CNPJ com máscara, dígito errado ou sequência repetida, e duplicado.** A máscara é aceita e normalizada para dígitos. Dígito errado ou sequência repetida dão 422 "CPF inválido."/"CNPJ inválido.". Um duplicado na mesma empresa dá 409, e o mesmo documento em outra empresa é aceito. Testes nas Tarefas 3 e 13.
4. **Planilha colada com decimal em vírgula, linha em branco, cabeçalho desconhecido ou nome de ambiente que não existe.** A importação aceita `1,5`, ignora linhas vazias e devolve todos os erros com o número da linha do Excel, sem gravar nada. Teste na Tarefa 16.
5. **Tarefa que levanta exceção, ou dois workers ao mesmo tempo.** A tarefa termina `falhou` com a mensagem, e o worker segue para a próxima. Uma tarefa nunca é reservada por dois workers. Teste na Tarefa 11. Cookie adulterado, sessão expirada ou usuário desativado dão 401 `nao_autenticado`, e o front-end volta ao login. Testes nas Tarefas 7 e 17.
